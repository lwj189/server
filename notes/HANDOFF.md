## 4. 已经掌握的概念（不用再从头看）

**socket 层**
- `socket / setsockopt / bind / listen / accept / read / send / close` 各自的生命周期和返回值语义
- 两个 fd 的角色：`server_fd`（总机）vs `conn_fd`（分机）
- `SO_REUSEADDR`（只允许覆盖 TIME_WAIT，不允许两个活着的监听进程）
- `listen` 的 backlog = accept 队列上限（`ss` 的 `Send-Q` 就是它）
- `accept` 的 `addrlen` 是**值-结果参数**（每轮都要重置）

**协议层**
- HTTP 消息分帧：头部用 `\r\n\r\n` 定界，body 用 `Content-Length` 定长（RFC 9112 §2.1 / §6.2 / §6.3）
- 头字段名**大小写不敏感**（RFC 9110 §5.1）；冒号后 OWS 可为 0 个（RFC 9112 §5）
- 状态码：200 / 400 / 413 / 431

**系统层**
- 字节序：`htons`（填进去）/ `ntohs`（读出来）
- `errno` 机制 + 错误三分类（可重试 `EINTR` / 可恢复 `EAGAIN`·`EMFILE` / 编程错误 `EINVAL`）
- TCP 是**字节流**：一次 `read` ≠ 一个请求（半包/粘包）
- TIME_WAIT、fd 会被复用、`SIGPIPE` 为什么必须忽略
- **epoll 三件套**（`epoll_create1` / `epoll_ctl` / `epoll_wait`）、非阻塞 `fcntl` 读-改-写、`EAGAIN` 四态、LT vs ET

（细节都在 `notes/epoll_notes.md` 和 `notes/learning_progress.md` 里）

→ **全部坑都在 `notes/pitfalls.md`**（症状速查表 + 根因 + 怎么验证）。
   遇到问题先查它最前面的「症状速查」，按现象找编号。

几条印象最深的，提醒自己这里记的是**结论**，验证过程在 `pitfalls.md`：

| 坑 | 一句话教训 |
| --- | --- |
| 假绿（验收标准本身没被验证过） | 要问"反例能不能通过"；通过了的测试也可能是假的 |
| `F_SETFL` 是**整体替换**不是按位加 | 必须 `F_GETFL` → `\| O_NONBLOCK` → `F_SETFL` 三步读-改-写 |
| `accept` 出来的 `conn_fd` **不继承**非阻塞 | 每个新 fd 都要自己设一遍 |
| `ENFILE` vs `EMFILE` | 一个是系统级 fd 用尽，一个是**本进程** fd 用尽，别混 |
| `EMFILE` 忙等 | 坏版本静置 2 秒 **+1,098,114 行**日志、CPU 67~75% 状态 `R`、已连上的用户还超时 |
| `inbuf` 处理完不消费（不 `erase`） | 同一批字节会被回两遍 |
| `paused_at` 记成 `0` | `size_t` 无符号 → `0 < 0` 永远不成立 → 话筒摘了就再也放不回去 |
| 答案写在 `/tmp` | `/tmp` 跨命令会被清掉，工作文件放项目里 |

## 6. 心智模型（我一直用这一套语言想问题）

- **总机 / 分机**：`server_fd` 是公司总机（固定号码，永久存在），`conn_fd` 是转接出去的分机（一通电话一个，挂断后号码会被复用）
- **餐厅等位区**：accept 队列；backlog 是等位区容量；队列满了不报错，只会"变慢"
- **水管 / 快递**：TCP 是**水管里的水**（字节流，没有边界），不是一箱一箱的快递
- **状态机切片**：epoll 改造的本质 = 把"一个连续执行的函数"改造成"每次事件恢复一点进度"，所以状态必须从栈上搬进 `ClientContext`
- **fd 是会被复用的号码**：`close(5)` 之后下一个连接很可能又拿到 5（实测三次连接全是 fd=5）
- **分帧（framing）**：所有基于流的协议都要自己定消息边界，这是 HTTP/1.1 用 `\r\n\r\n` + `Content-Length` 的原因

**CP6b 做了什么**：accept 之后不再立刻 close，而是

1. `conn_fd` 设非阻塞（`F_GETFL` → `| O_NONBLOCK` → `F_SETFL` 三步读-改-写）
2. `epoll_ctl(EPOLL_CTL_ADD)` 登记，`data.fd = conn_fd`
3. 事件循环里用 `events[i].data.fd` **分流**：总机 → `accept` / 分机 → `read`；
   分机循环 `read` 到 `EAGAIN`，`read()==0`（对端正常关闭）或出错时 `close` 配平

**CP6b 的验收**：当时的 `cp6b_test.py` **4/4 全绿**（这个文件现已改名 `tests/balance_test.py`，
echo 用例随 CP6c-2 退役，详见下一节）

```
[1] echo        分机收到的话原样送回                      ← 已退役（CP6c-2 换成 HTTP）
[2] 分多次到达   分 3 批发送都要收到（read 循环到 EAGAIN） ← 已退役
[3] 并发不串台   3 条连接同时保持，各收各的               ← 已退役
[4] fd 配平      开 20 条连接全关掉，fd 数回落到基线      ← 留下来了（与协议无关）
```

实测：连跑 3 次，基线**始终是 5**；累计 **78 条连接**进出，fd 数从头到尾没动过。

> ⚠ **这条判据是从一个"假绿"改过来的，别改回去。**
>
> 原来的写法是：*"同时开 3 个 nc 都不关，服务器打印的 fd 应该是 5、6、7"*。
> 但它对"分机到底进没进 epoll"**完全不敏感** —— CP6a 那份代码里 `close(conn_fd)`
> 是注释掉的（fd 全泄漏），跑同样的场景**照样打印 5、6、7**。

> | | 泄漏版（CP6a） | 配平版（CP6b） |
> | --- | --- | --- |

> | 跑 20 条连接后 | fd 11 → 31 | fd 5 → 5 |

>

> 坏版本确实能复现（想 `send` 1048576 字节 → 第一次只出去 **32741**，第二次 **47616**，第三次 `EAGAIN`），
> 但当前响应只有 117 字节，**根本撞不到**。按 TDD 规矩"**写不出会红的测试，就别改代码**" ——
> 现在改它等于盲改，改完也没东西能证明改对了。等响应变大 / 做长连接压测时再回来
> （那时要加输出缓冲 + `EPOLLOUT`，形状和 CP6d-1 的"暂停/恢复"是同一套）。

> 📌 **CP6d 的两个"不要原地重试"**：`accept` 撞 `EMFILE`、`send` 撞 `EAGAIN` ——
> 非阻塞 fd 上"现在做不了"的正确反应都是"**去等一个事件**"，绝不是"原地重试"。
> 原地重试就是忙等，就是 109 万行日志。

### CP6c-2 的验收：两套测试，**两个轴**

| | 测什么 | 命令 | 结果 |
| --- | --- | --- | --- |
| `tests/p2_test.py` | **协议正确性**（回答对不对） | 对着 `build/epoll` 跑 | **23/23** |
| `tests/balance_test.py` | **资源配平**（东西还没还回去） | `--pid <服务器pid> --log server.log` | **4/4** |

> 📌 **两个轴是正交的，一个全绿不代表另一个绿。** 实测（造坏版本验的）：
>
> | 坏版本 | p2_test 23 项 | balance_test |
> | --- | --- | --- |
> | 摘掉 EOF 路径的 `close` | **23/23 全过** | [2] 抓到（fd +10） |
> | 摘掉所有 `erase`（账本泄漏） | **23/23 全过** | [1][2][3] 全过，**只有 [4] 哨兵抓到（232 次）** |
>
> 所以两套都要跑 —— 这也是 CI 里 epoll 要跑两个脚本的原因。

> ⚠ **balance_test 自己踩过一个假绿**：8888 上残留着旧服务器时，`--pid` 指向新进程
> 但流量打到旧进程上，照样"4/4 全绿"。已加校验：**确认 `--pid` 就是该端口的监听者**，
> 对不上直接拒绝跑（退出码 2）。教训同上一条 —— **判据必须确认自己在量谁**。

> ⏱ **剩余路线的时间估算**（2026-10-02 估，放假期间）：CP6c-2 **4~7h** /
> CP6d 3~5h / day5 线程池 6~12h —— 合计 **14~25h，最可能 19h**。
> 拆分看：**到"事件驱动 HTTP 服务器"约 8~13h；再加线程池 +6~12h。**

> 📌 CP6c **不换 `data.ptr`**（原先这么写过，重新评估后否掉了）：
> `data.fd` 保持不变，另加一个 `std::unordered_map<int, ClientContext>` 账本。
> 理由：分流逻辑一行都不用改；`data.ptr` 还得引入"哨兵"来区分总机（指针没法跟
> `server_fd` 这个 int 比），而且查不到时 map 能 `continue` 兜住、悬垂指针直接炸。
> 账本无论如何都要有（所有权 + 谁还活着），那 `ptr` 就只剩"省一次哈希查找"这点收益。
> 详见 `learning_progress.md` 的 CP6c 小节。

> 📌 曾把"同批陈旧事件"列为 CP6d 的一项，**实测证明在本设计里不存在**
> （单线程 LT + 不 `dup()`：30000 条连接 / 65240 个事件，陈旧 0 个）。已划掉。

## 9. 学习方式上的一些结论

- ✅ **先弄懂"为什么"，再动手做"怎么做"**（比如先想清"阻塞的代价"，再上 epoll）
- ✅ **对比表格**（旧写法 vs 新写法，两列差异一目了然）—— 我记东西最靠这个
- ✅ **真实命令输出**（不是"应该会打印 xxx"，而是把实测结果记下来）
- ✅ **类比**（总机/分机、等位区、水管）
- ❌ 大段完整代码直接抄
- ❌ 一次上三个新概念（消化不了）

### 记录要简洁，但步骤要具体

我以前记东西容易越记越乱，回头自己都看不下去。所以这份笔记的写法是：

| 要求 | 具体做法 |
| --- | --- |
| **一条结论要短** | 能三行说清就别写三十行 |
| **步骤要具体** | 记到"能照着敲"的程度（一条命令 + 一个预期输出） |

| 笔记一长容易丢线索 | **关键信息要能重发 / 能重查**（别指望自己记得前面写过的） |

### ★ 编辑器的自动补全：答案先出来了，理解没跟上

写代码时编辑器会**把答案自动补出来**，手比脑子快 —— 代码是绿的，但那一行到底为什么这么写，说不上来。

实测：4 轮练习、共 15 个空，**能独立答出来的是 0 个**。

- CP6c-2 的 5 个空 → 被自动补全 → 当时的感受：*"自动补全了，但是不懂其他几个为什么那么填"*
- CP6d-1 的 5 个空 → 1 个填错（`ENFILE`/`EMFILE`），1 个明说"**是自动补全的**"

**解法一（留空但加问句）**：每个空旁边写一句**问句**，而不是只留下划线 ——

```cpp
const size_t total = ______;   // ← 空 4：一个完整请求 = 头部 + ？ + ？，一共多少字节？
```

空本身还是会被自动补上，但**问句把"该想什么"钉在那儿了**，写完之后顺着问句一个个讲。

**解法二（更彻底，2026-10-03 试出来的、2026-10-04 起在用）**：文件里**只写注释问句、不留下划线**，
那一整行语句由我自己敲。**"把空填上"和"把语句写出来"不是一回事** —— 后者才练得到 C++ 地基。

### ★ 我卡住的地方**大多不是 epoll**

这是最容易被误判的一条。按"卡在哪一层"分类（CP6c-2 / CP6d 实测）：

| 我卡住的 | 其实是 |
| --- | --- |
| `= 0` 是什么意思 | **C++ 默认参数** |
| `"\r\n\r\n"` 怎么填 | **C++ 转义字符 / 字符串字面量** |
| 参数去哪儿查 | **查资料的方法**（`man` 不管 C++ 标准库） |
| `bool want_close = true;` 为什么没用 | **成员访问要写 `ctx.`** —— 行首有类型 = 新建变量 |
| `Connection` 那段为什么错 | **照抄抄多了** —— 抄来的每一行得知道在干嘛 |

**结论**：地基在 C++，不在 epoll。**卡住时别急着往 epoll 上找原因，先看是不是 C++ 那层漏了。**

### ★ 一句话治好"什么都要自己推"：查 vs 定

我当时的原话：*"所以说这个状态机有许多需要自己推的东西是吧"* —— 这是被"什么都要自己想"压住了。

| | 来源 | 该怎么办 | CP6c-2 的例子 |
| --- | --- | --- | --- |
| **事实** | RFC / 手册 / 编译器 | **查**，别推 | `\r\n\r\n`、`npos`、`header + 4 + body` |
| **契约** | **自己定** | 推（设计），但全篇一致 | `true` / `false` 各代表什么 |

**5 个空里 3 个是查的、2 个是同一个设计决定。** 不是"许多要自己推"，
是"**一个契约要想清楚，其余去查**"。
