我卡在"STL 方法名怎么猜"上、完全没头绪时，这招一下通了：

```bash

grep -oP "^      \K[a-z_]+(?=\()" "$H" | sort -u
```

| 中文 | 英文 |
| --- | --- |
| 找 | `find` |

只差两个字母，而且**编译不报错**。详见第五节第 4 条。

### 两处哨兵（CP6c-1 的重要产出）

**主哨兵在 `emplace` 那一侧**（这段最值钱）：

```cpp
if (!clients.emplace(conn_fd, ctx).second) {
    std::cerr << "账本里已经有 fd=" << conn_fd << " —— 上一个连接漏了 erase" << std::endl;
}
```

**次哨兵在 `erase`**：`if (clients.erase(fd) == 0) { ... }`

**为什么主哨兵必须在 emplace**（实测踩出来的）：
漏了 `erase` 之后，旧条目还躺在账本里；下一个连接复用同一个 fd 时，
`erase` 照样能删掉它（返回 1）—— 所以 `erase` 那边**永远喊不出来**。
只有 `emplace` 这一侧才知道"这个号码不该有人占着"。

**实测效果**：故意删掉一条 `erase` → 测试**照样 4/4 全绿**（编译零警告），
但哨兵报了 **23 次**。**测试看不见的 bug，只有哨兵能抓。**

## 五、这一段踩出来 / 纠正过的东西（4 个）

### 1. `-Wconversion` 在 C++ 下**不含**符号检查

我一度说 `send(fd, buf, n, 0)` 会报 `-Wconversion` 警告 —— **说错了**。
实测：同一段代码 `gcc -Wconversion` 报，`g++ -Wconversion` **不报**，
要显式加 `-Wsign-conversion`。

### 2. "同批陈旧事件"**实测不存在**

我曾把它列为 CP6d 的一项（没验证过）。实测：

```
单线程 LT epoll + 不 dup()：
30000 条连接 / 65240 个事件 → 陈旧事件 0 个
```

原因：`epoll_wait` 对同一个 fd 每批只报一次；`accept` 只能复用"本批更早 close 掉"
的 fd 号，而那个 fd 的事件早已消费完。
`man 7 epoll` 那段警告针对的是 **`dup` 出来的 fd** —— 本设计没有 dup。
**已从 CP6d 划掉。**

### 3. `data.ptr` 设计被自己否掉

我一度写"CP6c 要 `data.fd → data.ptr`"。重新评估后否掉：
`data.fd` 保持不变 + 加 `unordered_map` 账本。理由：分流逻辑一行不用改；
`data.ptr` 还得引入"哨兵"区分总机，而且查不到时 map 能 `continue` 兜住、
悬垂指针直接炸。

### 4. 哨兵位置：先放 `erase`（错）→ 后放 `emplace`（对）

见第三节。**这是这一段最有价值的一课**：

> 漏 `erase` 这件事，编译零警告、测试全绿、服务器行为正常 ——
> 唯一的报警器就是你自己造的哨兵。
